# 팀 업무 분담

제철 수산물 시세 조회 서비스 (공개 서비스). 담당자 이름은 `담당` 칸에 채운다.

## 확정된 프로젝트 정의

- 사용자: 횟감을 사거나 외식하는 일반 소비자
- 지역: 동해 · 서해 · 남해 · 제주 4개 권역 (위치 기반 자동 선택 + 수동 변경)
- 제철 판단: 월 × 권역 고정 데이터
- 시세: 공공 API를 일 1회 수집해 Supabase에 저장, 화면은 저장값만 읽음
- 추천 라벨: 🟢 지금이 적기(제철 + 시세 ≤ 평년) / 🟡 제철이지만 비쌈 / ⚪ 비제철
- 음식 추천: AI(Haiku)가 어종당 1회 생성, Supabase에 캐시
- 로그인 없음(조회 전용), 가까운 횟집 검색 유지
- 배포: Vercel + Vercel Cron

팀이 6명보다 적으면 `A+C`, `D+F`처럼 묶는다. 묶기 좋은 쌍은 의존이 적은 순서대로 `C+B`, `D+F`다.

## 진행 순서와 의존성

1. **먼저 A**가 타입(`src/types/seafood.ts`)과 스키마를 머지한다. 나머지는 이 타입을 기준으로 시작한다.
2. A가 끝나기 전에도 B(API 조사), C(순수 함수), D(샘플 데이터로 UI)는 `src/data/seasonal.ts`의 샘플 타입으로 병렬 착수할 수 있다.
3. D는 C와 A가 머지된 뒤 실제 데이터를 연결한다. E는 A 이후 시작한다.
4. F의 배포는 마지막에 B(Cron)와 E(AI 키) 환경변수가 확정된 뒤 마무리한다.

```
A (스키마·타입) ──┬─▶ B (시세 수집) ──────┐
                  ├─▶ C (점수 로직) ─▶ D (홈 UI) ─┤
                  └─▶ E (AI 추천) ────────────────┼─▶ F (배포·통합 검수)
```

## 공통 규칙 (CLAUDE.md 요약)

- 브랜치는 `master`에서 `feature/기능명`으로 만들고, PR은 팀원 1명 이상 승인 후 병합한다.
- 커밋 제목은 `유형: 한 줄 요약` (feat, fix, docs, style, refactor, test).
- 머지 전에 `npm run build`와 `npm run dev`로 로컬 확인한다. PR 본문에 스크린샷 또는 작업 요약을 넣는다.
- 비밀 키는 `.env.local`에만 두고, 새 환경변수는 키 이름만 `.env.example`에 추가한다.
- 서버 컴포넌트에서 현재 날짜를 쓰면 `<Suspense>`로 감싸고 `connection()`을 호출한다.
- 이 Next.js 버전은 코드 작성 전 `node_modules/next/dist/docs/`의 해당 가이드를 확인한다.
